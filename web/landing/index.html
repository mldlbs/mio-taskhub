Why Mio-TaskHub
多个 Agent，各自为战
当你同时使用 opencode、Claude Code、Codex 时，每个 agent 都是一个信息孤岛。它们不知道彼此在做什么，无法共享进度，失败了也不会自动重试。
没有调度中心

Agent 各自为战

  • 手动在多个终端间切换，复制粘贴任务描述
  • 不知道哪个 agent 在执行什么，进度如何
  • 一个 agent 挂了，任务就丢了，需要手动重跑
  • 多个 agent 可能同时修改同一个文件，产生冲突
  • 需求到执行缺乏结构化流程，全靠口头描述
有了调度中心

统一调度，并行执行

  • 一个任务队列，所有 agent 共享，自动领取
  • 实时看板：谁在执行什么、进度多少、是否健康
  • 心跳检测 + 自动重试，agent 挂了任务自动回收
  • 依赖编排：前置任务完成后才放行下一个
  • 想法 → 讨论 → 评审 → 任务 → 执行，全链路结构化
Core Capabilities
为多 Agent 协作设计的每个能力
⚡

任务状态机

7 阶段研发流水线：brainstorming → design → planning → ready → implementing → review → done。每个阶段有明确的准入条件和产出物要求。

🔄

Agent 调度

注册 → 领取 → 心跳 → 提交。按优先级 + 关联度智能分配，超时自动回收，支持 agent 类型匹配和 fallback 降级。

🔗

依赖编排

depends_on 数组定义前置依赖，环检测防止死锁，前置任务完成后自动放行。支持全图和子图查询。

💡

想法工作台

记录想法 → 发酵讨论 → 评审决策 → 拆解为任务。版本历史追踪，ADR 自动投影到 Git 仓库。

🔌

MCP 原生

26 个 MCP 工具，任何支持 MCP 的 agent（opencode、Claude Code、Codex、Hermes）可直接调用，零适配成本。

📊

实时监控

自包含仪表盘：CPU/内存/线程/DB 连接池。24 条告警规则，OpenTelemetry 全链路追踪，结构化日志查询。

🌙

夜间执行

NightRunner 配置驱动，跨夜时间窗口自动 spawn agent 进程。睡前安排任务，醒来查看结果。

⏰

定时任务

CronEngine 定时调度，支持 create_task 和 webhook 两种动作。执行日志和历史可追溯。

📦

单文件部署

PyInstaller 打包为单个 EXE，SQLite 单文件数据库。无需 Docker、无需 Node.js、无需外部数据库服务。

How It Works

记录想法

讨论评审
多 agent 参与讨论，评审决策，拆解为具体任务

任务入队
任务进入队列，设置优先级、依赖、截止时间
4
Agent 领取
空闲 agent 自动领取任务，开始并行执行
5
监控交付
实时看板追踪进度，心跳保活，失败自动重试
# Agent 通过 MCP 工具与 TaskHub 交互
# 1. 注册
taskhub_register(name="opencode", agent_type="cli")

# 2. 领取任务
taskhub_claim(agent="opencode")

# 3. 上报进度
taskhub_heartbeat(run_id="run_abc123", progress=68)

# 4. 提交结果
taskhub_submit_result(run_id="run_abc123", success=True)

# 5. 查看看板
taskhub_status() # → 全局任务状态一览

Use Cases
真实场景，真实价值
🔀

多 Agent 并行编码

问题：一个需求拆成 3 个子任务，手动在 3 个终端分别启动 agent，复制粘贴描述，来回切换查看进度。
解决：创建 3 个任务设置依赖，opencode、Claude Code、Codex 各自领取执行，看板实时追踪。
结果：并行执行时间从 3 小时压缩到 40 分钟，无需手动协调。
🌙

夜间自动执行

问题：大量重复性任务（依赖升级、格式化、测试）占用白天编码时间。
解决：睡前在 TaskHub 排好任务队列，NightRunner 跨夜自动 spawn agent 执行。
结果：早上查看结果，夜间完成 15+ 个任务，白天专注创造性工作。
💡

需求发酵到执行

问题：脑子里的想法直接变成代码，缺乏设计和评审，返工率高。
解决：想法记录 → 讨论评审 → 结构化拆解 → 依赖排序 → agent 执行，全链路可追溯。
结果：需求质量提升，执行有据可查，版本历史完整保留。
🔄

失败自动恢复

问题：agent 执行到一半挂了，任务丢失，需要从头手动重跑。
解决：心跳检测 agent 存活，超时自动回收任务，指数退避重试，最多 10 次。
结果：任务完成率从 ~85% 提升到 ~98%，无需人工干预。
Why Not Just Use ChatGPT
不是另一个 AI 工具
Mio-TaskHub 不是 AI，不写代码，不做推理。它是让多个 AI Agent 协同工作的基础设施。

调度 不是任务列表

普通 TODO 工具只记录"要做什么"。Mio-TaskHub 管理"谁在做什么、做得怎么样、什么时候完成"——带心跳检测、自动重试、优先级调度的真正任务队列。

协调 不是单 Agent

ChatGPT/Claude 一次只能服务一个用户、一个任务。Mio-TaskHub 让 opencode 写代码的同时，Claude Code 在跑测试，Codex 在重构——三者共享同一个任务队列。

本地 不是云服务

SQLite 单文件数据库，PyInstaller 单个 EXE。数据在你本机，不上传任何外部服务。无需注册账号，无需 API Key，开箱即用。

MCP 不是私有协议

基于开放的 MCP 协议，任何支持 MCP 的 agent 都能直接接入。不锁定你用哪个 agent，不绑架你的工作流。
