为什么需要

Agent 之间互不通信。

每个 agent 都是一座孤岛。它不知道其他 agent 在做什么，无法共享进度，失败了也不会自动重试。

没有调度中心

手动协调

  • 在多个终端间切换，复制粘贴任务描述
  • 不知道谁在做什么，进度如何
  • Agent 挂了，任务丢失，需要手动重跑
  • 多个 agent 同时修改同一个文件，产生冲突
  • 从想法到执行缺乏结构化流程
有了 Mio-TaskHub

自动调度

  • 一个共享队列，agent 自动领取任务
  • 实时看板：谁在做什么、进度多少、是否健康
  • 心跳检测 + 失败自动重试
  • 依赖排序，防止冲突
  • 想法 → 讨论 → 任务 → 执行，全链路可追溯
核心能力

为多 Agent 协作而生。

任务状态机
7 阶段研发流水线：brainstorming → design → planning → ready → implementing → review → done。每个阶段有明确的准入条件和产出物要求。
Agent 调度
注册 → 领取 → 心跳 → 提交。按优先级 + 关联度智能分配，超时自动回收，支持 agent 类型匹配和 fallback 降级。
依赖编排
depends_on 数组 + 环检测。前置任务完成后自动放行下游。支持全图和子图查询。
想法工作台
记录 → 发酵 → 评审 → 拆解为任务。版本历史追踪，ADR 自动投影到 Git 仓库。
MCP 原生
26 个 MCP 工具。任何支持 MCP 的 agent（opencode、Claude Code、Codex、Hermes）零适配接入。
实时监控
内建仪表盘：CPU / 内存 / 线程 / 数据库连接池。24 条告警规则，OpenTelemetry 全链路追踪，结构化日志查询。
夜间执行
配置驱动的跨夜执行。按时间窗口自动 spawn agent 进程。睡前安排任务，醒来查看结果。
单文件部署
PyInstaller 打包为单个 EXE，SQLite 单文件数据库。无需 Docker、Node.js 或外部数据库。

MCP 交互示例
# Agent 通过 MCP 连接 TaskHub taskhub_register(name="opencode", agent_type="cli") # 领取下一个任务 taskhub_claim(agent="opencode") # → { task_id: "task_abc", title: "修复登录超时", priority: 1 } # 上报进度 taskhub_heartbeat(run_id="run_001", progress=68) # 提交结果 taskhub_submit_result(run_id="run_001", success=True) # 查看全局状态 taskhub_status() # → { queued: 2, running: 2, completed: 15, failed: 0 }
为什么不用 ChatGPT

不是又一个 AI 工具。

Mio-TaskHub 不写代码。它调度写代码的 agent。

调度 不是 TODO 列表

TODO 工具只记录"要做什么"。Mio-TaskHub 追踪"谁在做、做到哪了、还活着吗"——心跳检测、自动重试、优先级调度。

协调 不是单 Agent

ChatGPT 一次服务一个用户、一个任务。Mio-TaskHub 让 opencode 写代码的同时，Claude Code 在跑测试，Codex 在重构——共享同一个队列。

本地 不是云服务

SQLite 文件，单个 EXE。数据在你本机，不上传任何外部服务。无需注册账号，无需 API Key。

MCP 不是私有协议

开放的 MCP 协议，任何兼容 agent 直接接入。不锁定你用哪个 agent，不绑架你的工作流。
