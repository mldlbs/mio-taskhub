# ADR-001: ADR（架构决策记录） 管理

## Status

ACCEPTED

## Context

mio-taskhub 作为跨 agent 任务中心，架构决策（如 Outbox/Git Sync、状态机、ADR 流程本身）散落在代码注释与会话记忆中，缺乏可追溯的正式记录。团队需要在实施完成后将关键决策沉淀为可评审、可追溯的架构决策记录。

## Decision

采用 MADR 模板管理 ADR：1) ADR 作为 Idea 的演化形态（formed -> proposed），非独立实体；2) 生命周期 proposed -> accepted/rejected，accepted 可 deprecated/superseded；3) 数据库为 Source of Truth，Git 为只读投影；4) 采用 Outbox 模式异步同步——领域事件写 OutboxEvent 表，GitSyncWorker 轮询消费，一个事件一个 commit；5) 稳定 adr_number（ADR-001）与 UUID 分离；6) README.md 索引自动生成。

## Alternatives

A) 独立 ADR 实体表：与 Idea 体系割裂，需重复实现变更历史/讨论/评审；B) 同步写 Git（API 事务内 commit）：阻塞请求、事务失败导致不一致；C) 前端直读 Git 文件：破坏 DB 权威性，前端需解析 Markdown。

## Consequences

+ 决策可追溯、可评审，MADR 标准格式便于工具链处理；+ Outbox 保证 DB 与 Git 最终一致且 API 不被 Git 操作阻塞；+ 幂等 worker 支持安全重试。 - Git 投影有秒级延迟；- 需要维护 Markdown 渲染模板；- broken_down 想法需回流 formed 才能演化为 ADR（已支持）。
