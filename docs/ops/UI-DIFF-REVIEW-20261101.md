# hub.html 与当前界面差异评审（2026-11-01）

> 对象：`docs/ui/hub.html`（独立可交互原型，`hub.js` 使用 mock 数据，未接 API）
> 对照：当前 React 应用（`web/src`，Ledger 主题桥接后）
> 结论：**不建议直接替换**。原型是视觉与信息密度的目标稿，当前应用是真实数据与完整工作流；应按层移植，而不是整站替换。

## 1 一句话结论

| 维度 | hub.html 原型 | 当前应用 |
|---|---|---|
| 数据 | mock，硬编码 278 任务 / 1760 ev/min | 真实 API + WebSocket |
| 完整度 | 视觉完整、交互演示 | 功能完整、视觉部分旧 |
| 任务详情 | 概要 / 事件流 2 个 tab | 工作流 / 讨论 / 子任务 / 依赖 / 活动 5 个 tab + 文档 / 评审 / 门禁 |
| 直接替换风险 | 会丢掉真实数据、文档链、门禁、命令面板 | — |

## 2 结构与密度

| 项 | hub.html | 当前应用 |
|---|---|---|
| 顶栏高度 | 46px | 约 60px（padding 14px） |
| 侧栏宽度 | 52px | 66px |
| 导航项 | 13 个全部可见（含想法/定时/观测台/记忆） | 9 个视图入口 + 设置；4 个已下线到命令面板 |
| 主题切换 | 分段 light/dark 按钮 | 单按钮切换 + `?theme=` |
| 状态列 | 7 列，列头紧凑，卡片小 | 7 列，卡片更大、标签更多 |
| 字体 | Ledger（Inter/系统栈） | 已桥接 Inter，但仍有旧组件字号/字距 |
| 任务卡 | 标题 + ID/agent + 时长/时间，极少标签 | 标题 + ID + 阶段 + 优先级 + 项目 + 标签 + 时长 |
| 顶部指标 | 任务数/完成率/事件速率 | 任务数/完成率/事件速率（已有） |

原型更“Linear 化”：信息密度高、层级少。当前应用更“工作台化”：单卡信息多、操作入口多。

## 3 功能差异

### 原型有、当前没有（或较弱）

1. **统一紧凑顶栏**与分段主题切换。
2. **卡片级拖拽预览**与列内插入位（当前 BoardView 有拖拽，但视觉反馈不同）。
3. **抽屉式任务详情**（右侧滑出、概要/事件流两栏）。
4. 全站一致的 **状态色 7×4**（queued/claimed/running/retrying/completed/failed/cancelled）。
5. 更克制的空态与“载入更多”占位。

### 当前有、原型没有（不能丢）

1. 真实 API / WebSocket / 断线重连。
2. 新建任务完整表单、模板选择、依赖选择。
3. 命令面板 `Ctrl+K`、快捷键。
4. 任务详情的工作流/讨论/子任务/依赖/活动五个 tab。
5. 文档面板（requirement/spec/api/plan/review/test 等）、评审队列、门禁清单、证据卡。
6. 素材面板真实数据、Mio 运行时、观测台真实指标。
7. 错误/加载/空态、确认弹窗、toast、无障碍焦点管理。

原型中的“门禁 5 项”是 `gateOf(t)` 生成的假数据；不能作为真实门禁实现。

## 4 视觉差异（已截图）

- 原型：`docs/ui/screenshots` 之外的 `hub-prototype.png`（本地临时截图）。
- 当前：`docs/ui/screenshots/workflow.png`、`contact-sheet.png`。

主要差异：

| 项 | 原型 | 当前 |
|---|---|---|
| 主色 | 靛紫 `#6f68f7` | 已改为靛紫，但部分旧组件仍用青柠残留 |
| 状态色 | 蓝/绿/红/灰，饱和度低 | 运行=靛紫、完成=绿、失败=红；个别硬编码 |
| 玻璃 | 轻、薄、低对比 | 更厚、更强高光/投影 |
| 卡片 | 小圆角、细边框、紧凑 | 大圆角、玻璃高光、信息更密 |
| 排版 | 12–13px 为主 | 13–14px，标题更重 |

## 5 迁移建议（按增量）

### Phase 1：壳层（2–3 天）

- 顶栏 60 → 46px，侧栏 66 → 52px；中文 12px 最小字号验证。
- 分段主题切换替换单按钮。
- 导航：是否恢复 4 个已下线入口需产品决定；建议保留当前 9 项 + 命令面板。
- 保留现有 `MissionBar` 数据逻辑，只换布局/样式。

### Phase 2：看板与卡片（3–4 天）

- 卡片改为原型的信息层级：标题、ID/agent、时长/时间；项目/标签折叠到 hover/详情。
- 状态色统一从 `constants.js` 映射，不在组件里硬编码。
- 拖拽反馈与列内插入位对齐原型；保留现有 `onMove` 校验。
- 7 列在 1366×768 下横向滚动/缩窄策略需实测。

### Phase 3：任务详情（5–7 天，或 2 天做“壳”）

- 方案 A（推荐）：保留现有 6-tab TaskDetail，套用原型的抽屉壳、头部、按钮、门禁样式。
- 方案 B：按原型重写为 2-tab，会丢文档/评审/工作流，不建议。
- 文档链、门禁、证据卡必须保留。

### Phase 4：其余视图（5–7 天）

列表、拓扑、甘特、统计、观测台、记忆、素材、设置逐页对齐；每页保留真实数据/筛选/空态。

### Phase 5：验收（2–3 天）

- 1440/1600/1366 三档截图对比；
- 键盘/焦点/对比度；
- 真实数据回归：加载、断线、空态、错误；
- 暗/亮双主题逐页截图。

**总计约 15–20 人日；只做 Phase 1–3 约 6–8 人日。**

## 6 风险

1. 原型没有加载/错误/空态；直接照搬会引入“假数据 UI”。
2. 原型恢复全部 13 个导航项，与 2026-10-28 的“导航精简 13→9”冲突，需产品确认。
3. 46px 顶栏 + 52px 侧栏在中文/高 DPI 下可能拥挤，需 1366×768 实测。
4. 状态色若在组件内硬编码，会与后端状态机脱节。
5. 浅色主题仍有旧硬编码色，逐页验收前不能宣称双主题完成。
6. 原型无命令面板/文档/评审，移植时不能删现有能力。

## 7 建议决策

- **不替换 React 应用**；
- 以 `hub.html` 为目标视觉，按 Phase 1→3 增量移植；
- 先做“壳层 + 看板卡片 + 任务详情抽屉壳”，保留现有真实功能；
- 导航是否恢复 4 项、密度是否接受，需要一次产品确认后再进入 Phase 2。
