## 🔙 背景与问题

现状：mio-taskhub 的想法（Idea）只有 title/description 自由文本，缺目标、成功标准、范围、风险等结构化表达；想法评审靠自由式「开会」讨论，无角色、无固定输出物，讨论完结论散落，闭环断在最后一米。

痛点（真实场景）：

1. **方向不可见**：想法详情页看不到「目标是什么、成功标准是什么、现在该干什么」，推进靠翻聊天记录；
2. **假设与任务两套数据**：Mio 发酵的假设/打分与 taskhub 的想法互不关联，验证状态无处呈现；
3. **高风险无信号**：涉及钱/合规/用户数据的想法与普通想法外观一致，P2 需要的红队默认介入没有判定依据；
4. **数据模型未定型**：若 P0 不一次性补齐字段，P1/P2 每期都要改表结构，返工成本逐期放大。

为什么现在做：设计稿 v1.2 已经两轮评审冻结、开放项清零、P0 交付顺序明确；继续拖只会让后续假设关联（P1）与结构化评审（P2）失去承载底座。

---

## 📌 概述

想法落地缺的不是讨论，是结构化字段 + 串起来的数据 + 一屏可见且能推进的驾驶舱。本规格定义 P0 范围：Idea 结构化字段、cockpit 聚合端点、驾驶舱只读分节渲染、下一步动作规则引擎、高风险标签判定、任务图简化渲染。

> **守则**：字段模型一次定型，P0 后不改模型；每区块独立降级，任何外部依赖不得拖垮整包。

## 🎯 目标与非目标

| 类型 | 内容 |
|---|---|
| ✅ 目标 | 想法具备目标/成功标准/范围/风险等结构化表达；一屏看到推进状态与下一步动作 |
| ✅ 目标 | 高风险想法可被识别（为 P2 红队默认值铺路） |
| 🚫 非目标 | 假设实时分数（P1）、结构化评审/行动项（P2）、完整任务拓扑与复盘（P3） |
| 🚫 非目标 | 假设独立关联表、prompt 数据库配置（P2+） |

## 📦 范围（P0）

| # | 交付项 | 说明 |
|---|---|---|
| 1 | Idea 字段 + POST/PATCH | 8 字段全可空，变更进 IdeaChange diff |
| 2 | `GET /ideas/{id}/cockpit` | idea 聚合 + 区块级 sections 骨架 |
| 3 | 驾驶舱只读分节渲染 | 下一步动作置顶 + 8 区块 |

| 5 | tags 高风险判定 | tags ∩ 常量词表，env 可覆盖 |
| 6 | 任务图 P0 | 一层下游 + 环降级 + >20 折叠 |

## 📋 功能需求（FR）

| FR | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-1 | `Idea` 新增 8 个可空字段：`goal`、`success_metric`、`constraints`、`out_of_scope`、`assumptions`(JSON)、`risks`(JSON)、`mvp_scope`、`tags`(JSON) | P0 | 旧数据 NULL 全页面无异常；字段模型定型 |
| FR-2 | `POST /ideas`、`PATCH /ideas/{id}` 接受新字段；每次变更产生 `IdeaChange` diff 记录，JSON 字段 diff 键支持 `assumptions[hid]` 形式 | P0 | 并发两次单条回写均进 diff、无丢更新 |
| FR-3 | `GET /ideas/{id}/cockpit` 返回聚合结构：`sections[x].status/reason/cached_at` + `next_action`；P0 仅 idea 字段区真实聚合，其余区块空壳 `status:ok` | P0 | 响应结构符合设计稿示例；无整包 degraded 字段 |
| FR-4 | cockpit 单区块超时/失败仅该区块 `status=degraded`，其余区块正常，接口整体不 500 | P0 | 超时预算：Mio 3s / 其余 1s / 总 5s，并行聚合 return_exceptions |
| FR-5 | 驾驶舱详情分节渲染 8 区块，顺序：下一步动作置顶 → 目标与成功标准 → 假设 → MVP → 任务图 → 风险与依赖 → 审批点 → 复盘；空字段灰显引导 | P0 | 空壳区块渲染不报错 |
| FR-6 | 下一步动作按 5 级默认优先级序取第一条命中：缺 goal/success_metric → doc 未批准 → blocked 任务 → 未验证高风险假设 → 评审缺行动项；优先级序可配置 | P0 | 多条件同时命中只显示最高序一条 |
| FR-7 | dismiss 存服务端用户偏好表 `{user, rule_id, dismissed_at, condition_snapshot}`；`condition_snapshot` 为结构化布尔位（不存文本）；关键位变化立即复活，否则 7 天过期 | P0 | dismiss 后条件变化立即复活；非 localStorage |
| FR-8 | 高风险判定：`idea.tags ∩ 可配置关键词表` 非空即高风险；词表默认 `["高风险","合规","用户数据","花钱"]`，环境变量覆盖；P0 硬编码常量 + env，P2 迁 DB；不做正文匹配 | P0 | 命中词表输出 high_risk 标记 |
| FR-9 | 任务图 P0：显示直接关联任务 + 一层**下游**（谁依赖我）；检测到依赖环 → 降级为任务列表 + 警告条；超过 20 个默认折叠可展开 | P0 | 环场景不渲染拓扑；>20 折叠 |
| FR-10 | 现有行为回归：`mode=free` 讨论、既有 idea 编辑与评审流程不受本需求影响 | P0 | 全量 pytest 绿 |

| NFR | 描述 |

| NFR-1 | 兼容性：新字段全可空，旧数据零迁移；SQLite JSON 列复用现有迁移机制 |

| NFR-5 | 测试：新增用例覆盖优先级序、dismiss 复活、区块级降级、环降级；全量基线不回退 |

## ✅ 验收标准

1. 旧 idea 数据（NULL 新字段）全页面无异常
2. `PATCH` 新字段产生 IdeaChange diff（含 `assumptions[hid]` 键）
3. 优先级序生效：多条件命中只显示最高序一条
4. dismiss 后 `condition_snapshot` 变化立即复活（服务端存储），7 天自然过期
5. 高风险判定 = tags ∩ 常量词表，非空即高风险
6. 任务图：有环降级列表 + 警告、>20 折叠、下游方向
7. `/cockpit` 单区块超时仅该区块 degraded，整包不 500
8. `mode=free` 回归不受影响
9. 全量 pytest 绿 + 新增用例覆盖 FR-6/FR-7/FR-4/FR-9
