## 0. 执行摘要（结论与推荐）

**核心结论**：

1. **taskhub「过程合规」已做约 90%，「结果可信」为 0%**——文档链、状态机、读证、棘轮锁住了流程，却锁不住「Agent 说做完了」这一句话（submit_result 只校验所有权/状态/读证指纹，Agent 自报 success 被直接采信）。
2. **对外商业化路径被三重否决**：A-7（纯自用无法货币化）+ A-9（补三缺口只是追平 Qodex/CodeRabbit/Codex 已产品化的能力）+ A-11（自托管生态位是需求真空非竞争真空，ALM 品类已把追溯价值占满 20+ 年）。SOM 上界约 90 万元/年，低于单人 1 人年机会成本。
3. **推荐战略**：「单开发者自用过程质量工具 + 开源作品/方法论参考实现」双身份；不以营收立项；投资封顶**基准档 7 人日 / 10 天**（6 个验证实验 + 1 个只读假门，不是功能清单）。
4. **唯一决定性前置实验是 E1**（1.5 人日）：回溯审计近 60 天 success Run，看「合规但没干活」是否真实发生过。≥15% → 锁定自用；<5% → 整体暂停（将是第二次「机制成、价值败」，继 2026-10-08 创意闭环之后）。
5. **对外叙事只讲「可读性」**（把 Agent 的 Run 变成人能读懂的一段话），禁用「可审计/可追溯/证据链/防篡改/法律效力/ALM」等卖点词。

**推荐下一步（优先级序）**：

1. 跑 E1/E5/E6 三线并行（均只读，3 天内出结果）
2. E1 结果出来前，功能代码只做 FR-07 只读 diff 路由（0.5 人日）
3. D8-D9 汇总裁决，按决策树走 A/C 分支

## 2. 市场与竞品分析（明察，已联网核实 2026-11-03）

### 2.1 三重否决

| 判断 | 结论 | 关键依据 |
|---|---|---|
| A-7 价值依赖走向他用 | 成立 | 纯自用只解决「自己不被骗」，无法货币化 |
| A-9 无对外差异点 | 成立且比预期严重 | Qodex/Ito 每条 finding 带沙箱运行证据；CodeRabbit pre-merge checks；Codex 可导出 JSONL 审计；Claude Code git 级 AI authorship——补完三缺口只是**追平** |
| A-11 自托管生态位 | 不成立 | 机制组合确实空（读证 sha256/422、极简单人实现、exe 零依赖），但 ALM 品类（Polarion/Codebeamer/Jama/Helix/Ketryx）已把需求追溯全做完 20+ 年。taskhub =「ALM 追溯矩阵的极简复刻 − 法律效力」。**空位是需求真空（no buyers），不是竞争真空（no competitors）** |

### 2.2 市场规模（估算区间，用于立项门槛而非营收预测）

| 层 | 结果区间 | 说明 |
|---|---|---|
| TAM | 约 200亿–400亿元/年 | ARR 加总口径（Copilot/Cursor/Claude Code/审查类/Agent 治理类合计 $3.1–5.7B） |
| SAM | 约 5亿–30亿元/年 | × 证据/门禁诉求 10-25% × 自托管偏好 15-30% |

**立项门槛结论**：SOM 上界低于单人 1 人年机会成本 → 不应以营收为目标立项。

## 3. 产品战略（远山，条件式）

### 3.1 定位

**「单开发者自用过程质量工具 + 开源作品/方法论参考实现」双身份。**

| 为谁 | 不为谁 |
|---|---|
| 本人；S4 框架作者/方法研究者；S1 中可读性诉求的观察者 | S2 团队（缺 SSO/RBAC/审计）；S3 合规试点；付费买家；任何需法律效力的场景 |

对外口径**只讲可读性**；禁用词：可审计、可追溯、证据链、防篡改、法律效力、ALM 追溯矩阵（+ 高风险近义词：审计轨迹、溯源、存证、问责、不可抵赖、信任基础设施等）。

### 3.2 商业模式裁决

- 收入流 = **0**。开源作品模式的真实回报：引用/口碑、个人品牌、可复用基础设施（22 类文档链+47 MCP 工具+exe 打包）、求职作品集、**负面结论资产**（三重否决+创意闭环失败裁决的可讲性）
- 商业化重启需**四条 AND 缺一不可**：①E6 ≥3 条真实买家信号且 A-13 证实 ②S4 规模信号（≥500 star，或 ≥3 外部 PR/fork，或 ≥2 次引用/求部署）③不做清单 #5 书面解禁 ④E1≥15%。齐备后只开一次重评窗口

### 3.3 投资配比与规模封顶

| 档 | 人日 | 包含 | 不含 |
|---|---|---|---|
| 保守 | 3 | E1+E5+E6+否证清单/README | 任何功能代码、E2/E3/E4、S1.4 |
| **基准（推荐）** | **7 / 10 天** | 全套 E1-E6；S1.3 由 E3 假门复用承载 | 全量 S1.1/S2.1/S3.1、S4.x、对外功能 |
| 进取 | 12-15 | 基准 + S1.4 + S3.3 + E1≥15% 后 S1.1 + 开源发布/长文 | 仍不做 S2.1、S3.1/3.2、S4.x |

**封顶硬口径**：总量 ≤7 人日/10 自然日；E1 出结果前功能代码 ≤1 人日（仅 S1.3）；单功能 ≤2 人日；新增文档 kind 0、状态机 0、接口 ≤2、外部依赖 0、LLM 调用 0；10 天内 E1 未出结果自动降保守档。

### 3.4 条件分支与改道预案

| 触发 | 调整 |
|---|---|
| E1 ≥15% | 锁定自用，启用 S1.3+S1.4；S1.1 须再过 A-1 并单独裁决 |
| E1 5-15% 灰区 | 扩窗至 90 天复核**一次为限**，仍灰按 C 处理（禁止加样本洗阳性） |
| E1 <5% | 整体暂停，回 OST 重找机会；触发历史重复复盘「为何两次把机制当价值」 |
| E2 问A 占优 | 强化 S1.4，对外继续讲可读性 |
| E2 问B 占优 | 不翻案：S1.1 列候选，需 A-1 通过+E1≥15%+书面裁决 |
| E6 ≥3 / <3 | ≥3 → 开一次 A-13 重评窗口；<3 → 对外收缩纯作品位 |
| A-8 证伪 | 封顶可上调至进取档，仍不以营收为目标 |

### 5.3 发布纪律

1. **E1 判定落定前，任何对外发布动作不启动**
2. 禁用词在一切发布物中零出现。清单分层：PRD 侧最低约束（可审计/可追溯/证据链/防篡改/法律效力/ALM）+ GTM 侧扩展清单（另含审计轨迹/溯源/存证/问责/不可抵赖/防伪/责任链/合规效力/企业级合规/信任基础设施 10 个近义词），**以扩展清单为准**，发布前关键词自检由 v0.9 发布 checklist 承载
3. 负面结论固定句式：「我们试了 X → 结果 Y → 判定标准 Z → 暂停」——先给标准再给结论，不道歉不辩解
4. 负面结论怎么讲不劝退：把否证写成方法的一部分
