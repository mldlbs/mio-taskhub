## 1. 背景与问题陈述

- mio-taskhub 当前「过程合规」已做到约 90%（22 类文档链 + 9 条状态机 + 质量门 ≥80 + 读证 422 + 棘轮 + pre-push FR 校验），但「结果可信」为 0%。
- 已实证的边界（2026-10-10 源码审计）：
  - 无变更识别：全仓无 git diff / changed_files 逻辑，Run 无法绑定实际改动。
  - 无测试执行：全仓无 pytest runner，test 只是一种文档 kind。
  - 评审无身份隔离：submit_result 成功路径只校验 Run 所有权/状态/读证指纹，Agent 自报 success 被直接采信。
- 存在一条完全合规但结果不可信的路径：写好文档 → 够 80 分 → 读证齐全 → 自报 success → 自己 approve。
- 前置未决问题（A-2）：历史数据中「合规但没干活」是否真实发生过——这决定后续所有能力投资是否成立，**必须先验证再投资**。
- 历史教训：2026-10-08 创意生成闭环裁决「机制验证成功、价值验证失败、暂停」。本轮纪律：验证优先于功能，防止第二次同型失败。

### FR-01 E1 回溯审计

- 用户故事：作为唯一用户，我希望知道近 60 天被标 success 的 Run 中有多少没有真实代码改动，以便决定「结果可信」这条线是否继续投入。
- 验收标准：
  - Given 近 60 天 status=success 的 Run 集合，When 执行只读审计脚本，Then 产出报告含：窗口起止、样本总数、可判定数、unknown 数及原因、no_change 数与命中率、判定标签定义（has_change/no_change/unknown）、逐条 run_id+claim/submit 双时间戳+commit 或「无」、只读声明、结论三选一（≥15% / 5-15% / <5%）、扩窗次数（0 或 1）、生成时间、FR-01 引用。
  - 边界：取不到 commit 的样本计 unknown 单列、不入分母；可判定数 <10 → 标 INSUFFICIENT_DATA，扩窗至 90 天一次为限，仍不足则整体暂停、不得推断。
  - 失败路径：任何写库或状态机变更发生 → 实验作废并记事故行。
- 预估：1.5 人日。

### FR-02 E2 双问访谈

- 用户故事：作为唯一用户，我希望把「可读性」「可信性」拆成两问分别作答留痕，以便不被自己的确认偏误带偏。
- 验收标准：
  - 问A（可读性）：「上次 Agent 改了 ≥10 个文件，你怎么搞懂它改了什么、花多久」。
  - 问B（可信性）：「上一次 Agent 说做完了但你后来发现没做完，是什么时候、怎么发现的」。
  - Given 3-5 位同行受访者，When 分次独立记录两问原文，Then 各自独立成文留痕；禁止同一会话连答。
  - 判定：问B 命中 ≤1/5 → 「反造假」定位不成立；问A 命中只用于估 O1 规模，不计入 A-1。
  - 失败路径：任一问未留原文 → 判未执行，对应分支不得解锁。
- 预估：1.0 人日。

### FR-03 E3 只读 diff 假门

- 用户故事：作为唯一用户，我希望在提交结果前有一个只看变更的只读入口并观察自己是否真会用，以便用行为数据而非想象决定是否投功能。
- 验收标准：
  - Given FR-07 已上线，When 10 天窗口内每次 submit_result 前访问只读 diff 入口，Then 本地 jsonl 追加计数（run_id/ts/action/http_status/fr_ref）。
  - 判定指标：view_count、distinct_days、view_rate=有查看的 submit 数÷总 submit 数；自用每周 ≥5 次且 ≥3/5 同行用过 ≥1 次 → 对自用有价值。
  - 边界：纯本地、不联网、不回写数据库。
  - 失败路径：FR-07 非 200 或引用不存在的 FR-n → 计 error 行、不入分母。
- 预估：0.5 人日。

### FR-04 E4 严格模式开关（临时实验装置）

- 用户故事：作为唯一用户，我希望临时打开只校验「变更识别」段的严格开关跑 ≥10 次 submit_result，以便把这段机制的真假单独测出。
- 验收标准：
  - Given 本地配置 strict_change_only=true，When 执行 ≥10 次严格 Run vs ≥10 次对照 Run，Then 输出 pass/fail+原因码与多耗轮次对比。
  - 判定：多耗 ≤2 轮/Run 且 0 次伪造且 ≥8/10 一次通过 → 可升级为默认；平均多耗 ≥4 轮或 ≥2 次伪造 → 降级为只读观测。
  - 边界：开关只影响变更识别段；实验结束后移除（临时装置，不计入 E1 前功能代码口径，A-P5）。
  - 失败路径：实验结束未移除开关或未留回放记录 → 判未完成。
- 预估：0.8 人日。

### FR-05 E5 submit_review 回放

- 用户故事：作为唯一用户，我希望把历史 submit_review 原样只读回放，以便观察评审结论与文档内容是否存在可对应关系。
- 验收标准：
  - Given ≥15 条历史 review 记录，When 只读回放，Then 输出 review_id/reviewer 字符串分布/结论长度/是否关联 FR-n。
  - 判定：模拟硬隔离规则（reviewer≠executor）阻塞率 ≥50% → 单人场景不可行；≤20% → 可实施。
  - 边界：全程只读，不触发 409 写入、不改状态机。
  - 失败路径：任一写入发生 → 作废记事故行。
- 预估：1.0 人日。

### FR-06 E6 真实买家信号检索

- 用户故事：作为唯一用户，我希望如实记录「搜不到买家」而非「搜不到竞品」的证据，以便判断对外收缩到什么程度。
- 验收标准：
  - Given ≥8 条预设检索词，When 在 Plane/Huly/Gitea/Forgejo/Woodpecker/Langfuse issue 区 + HN + r/selfhosted + r/ExperiencedDevs 逐条检索，Then 每条留 query/日期/平台/命中数/是否真实买家信号（一句话依据）/链接或截图路径。
  - 判定：<3 条 → 不成立，对外收缩纯作品位；≥3 条 → 仅支撑作品位，不构成产品定位。
  - 边界：检索词表先固化再检索；纯文本/CSV 落盘，不引外部依赖、不写库。
  - 失败路径：以「搜不到竞品」替代或未留检索记录 → 判未执行。
- 预估：1.2 人日。

### FR-07 只读 diff 路由（唯一 E1 前功能代码）

- 用户故事：作为唯一用户，我希望用只读接口拿到本次任务的变更文件与聚合统计，以便提交结果前自己核对一眼。
- 验收标准：
  - Given 一个存在且有权读取的任务，When GET 只读路由，Then 返回 changed_files[] 与 stat，文件标注关联 FR-n，映射缺失标 UNMAPPED。
  - 边界：无变更 → 200 空集；任务不存在 → 404；不可读 → 403；不得 500；任何写方法 → 405。
  - 约束：不触发状态机、不写质量分、不新增文档 kind；实现为文件级 mtime/size + stat 聚合（本仓无 git diff 逻辑，不引 git 依赖；行级 diff 即超 0.5 人日，降级移交 Next，A-P6）。
  - 测试：实现与 pytest 用例注释均引用 FR-07，新增用例 ≥3，棘轮总数只升不降。
- 预估：0.5 人日。

## 6. 决策门与判定标准

| E1 结果 | 动作 |
|---|---|
| ≥15% | 锁定自用，启用 FR-07 常态化 + 池3 最便宜项按分支解锁 |
| 5-15% 灰区 | 扩窗至 90 天复核一次为限，仍灰按 <5% 处理（禁止加样本洗阳性） |
