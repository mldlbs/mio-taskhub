## 2 标签定义

### 2.1 `label_kind`（真实类型）

| 值 | 定义 |
|---|---|
| `signal` | 外部世界发生的具体事件、发布、事故、政策或可核验的技术主张 |
| `fact` | 对系统当前状态、行为、配置或既有事实的描述 |
| `result` | 一次任务/实验实际做成了什么（测试、构建、部署、验证结果） |
| `problem` | 一次失败、错误、超时、缺陷或根因 |
| `decision` | 已确认的需求、评审结论、讨论结论或选择 |
| `lesson` | 可复用的注意事项、坑或操作建议 |

`label_kind` 与提取器 `kind` 不同时，记为**分类错误**；不因“改个类型还能用”而算对。

### 2.2 `label_usable`（是否可入库引用）

一条素材标 `yes` 必须同时满足：

| 编号 | 条件 |
|---|---|
| U1 | **自包含**：脱离原文也能读懂在说什么；不是标题残片、纯标识符、裸名词 |
| U2 | **原子**：≤240 字符，≤2 个句末标点，≤2 个编号项 |
| U3 | **有主张**：包含谓词/结论/事件（“必须/返回/新增/失败/发布/加入/通过”等） |
| U4 | **非样板**：不是导航、登录、订阅、评论区等页面文字 |
| U5 | **非截断**：不是半截堆栈、半截路径、工具输出碎片 |
| U6 | **非泛化状态**：`agent offline`、`heartbeat timeout`、`never started` 等单独出现不算可用证据 |
| U7 | **非重复**：近重复只保留一条，另一条 `label_duplicate_of` 指向主条 |

`label_usable=no` 不等于“内容是假的”；它只表示“不适合作为一条可独立引用的素材”。

### 2.3 其他标签

| 字段 | 值 |
|---|---|
| `label_duplicate_of` | 近重复时填主条 `material_id`，否则空 |
| `label_confidence` | `high` / `medium` / `low`；规则双遍一致为 high |
| `review_status` | `reviewed` / `contested`；本次 11 条争议经裁决后全部 reviewed |
| `label_notes` | 错误类型、裁决理由或边界说明 |

## 3 边界案例

| 场景 | 规则 |
|---|---|
| HN 标题是问句（`Ask HN`、`What is…`） | 不算 signal；无具体事件/主张 → no |
| HN 裸产品名/版本号（`OpenSSH 10.6`、`Bevy 0.20`） | 没有说明“发生了什么” → no；`Picard 3.0 Released` 有发布动词 → yes |
| HN 观点/评论（`Why we're watching…`、`Maybe a better way…`） | 无具体事件 → no |
| GitHub 仓库描述 | 有具体能力/规格且 ≤240 字 → yes；纯营销长文 → no |
| 需求文档 `FR-n` 行 | 有明确要求谓词且 ≤240 → yes；只有“AC-1、AC-2”“AC-7b 前置”等残片 → no |
| 评审结论 | 先判断是“通过/批准/噪声告警关闭”还是“不通过/驳回”；不能因文本里出现“零失败”就判 problem |
| 讨论结论 | 按编号项切分；单项 ≤240 且自包含 → yes；多主题长段 → no |
| run.result | 测试/构建/验证结论 → result；纯行为描述 → fact；坑/注意 → lesson；工具失败碎片 → problem 但通常 no |
| run.failure | 有具体错误/异常/退出语境 → problem；`agent offline`/`heartbeat timeout`/`never started` 单独出现 → no |
| 日志/堆栈 | 有具体错误消息 → 可评估；只有 `node:internal/...` 半截堆栈 → no |
| 近重复 | 保留信息更全的一条；`diagram-design` 42 vs 44、`What Is/What is Codemode` 已标记 |

## 4 争议处理

1. **双遍规则**：pass1 较宽（≤300 字/≤3 句），pass2 较严（≤240 字/≤2 句/≤2 编号项）。
2. **争议标记**：两遍不一致 → `contested`，不进入金标准。
3. **人工裁决**：11 条争议全部按 v1.1 判 `no`（非原子长段），保留 pass1/pass2 差异在 `label_notes`。
4. **系统性误判**：`doc.review` 的“验收通过…零失败…”被关键字误判为 problem；19 条统一按决策/验收结论修正 `label_kind=decision`，但**仍计入分类错误**。
5. **不追求一致率**：本次没有第二个人工标注者；一致率只能说明规则稳定，不能说明标签正确。

## 6 指标定义

| 指标 | 定义 |
|---|---|
| 分类准确率 | `label_kind == kind` 的比例 |
| 误收率 | active 样本中 `label_usable=no` 的比例 |
| 漏收率 | quarantine 样本中 `label_usable=yes` 的比例 |
| 可用率 | `label_usable=yes` 的比例 |
| 加权估计 | 按各层 `active_eligible` 加权；只覆盖有样本的 5 层 |
| 证据不足 | active 样本 <20，或该层无 quarantine（漏收不可估） |
