## 认证与鉴权

- **无认证**：本地单用户服务，不校验 token/cookie，不存在 401 态。
- 403 表示「已识别调用方但越权」，本任务涉及的读取端点不产生 403。
- 读取端点无所有权概念，鉴权靠回环可达性边界。

## 通用响应结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| （数组） | array | 是 | `GET /tasks` 直接返回**裸数组**，元素为任务对象；本次**不变** |
| （对象） | object | 是 | `GET /board/summary` 返回对象，键名与层级不变 |
| `detail` | string \| object | 失败时必填 | 失败详情；对象形态含 `code` 与 `message` |

- `data` 为 `null` 与 `data` 为 `{}` 语义不同（前者=查询成功但无实体，后者=实体存在但字段为空）。
- `GET /tasks` 是**裸数组**返回（不是 `{data: [...]}` 包裹）——这是既有约定，本次**保持不变**，不得"顺手规范化"。

## 统一错误码

| HTTP | 业务码 | 含义 | 触发条件 | 本次是否变化 |
|---|---|---|---|---|
| 400 | `task.invalid_state` | 非法 state 入参 | `state` 不是合法状态枚举 | **不变** |
| 400 | `task.invalid_stage` | 非法 stage 入参 | `stage` 不是合法阶段枚举 | **不变** |
| 404 | — | 资源不存在 | id 查不到 | **不变** |
| 422 | — | 入参校验失败 | 缺必填字段 | **不变** |

## 字段命名与类型规范

- 命名风格：snake_case；布尔用 `is_` 前缀；ID 为 8 位十六进制字符串。
- 反例：`taskTitle`、`IsDone`、`task-state` 一律不用。
- 「字段缺失」与「显式 null」语义不同：缺失 = 服务端未产出该字段；`null` = 服务端明确表示无值（如 `due_at` 为空）。
- 计数类字段一律整数，不返回字符串。
- 布尔字段一律 JSON 布尔。

**列投影专项约束**：投影字段集必须与响应 dict 实际使用的字段**一一对应**——少一个则响应缺键（破坏契约），多一个则白白反序列化。本约束由测试用例 TC-2 的字段级 diff 兜底。

## 接口明细

### GET /api/v1/tasks

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 默认 | 约束 | 示例 |
|---|---|---|---|---|---|---|
| `state` | query | string | 否 | 全部（除取消态） | 非空时必须是合法状态枚举，否则 400 `task.invalid_state` | `queued` |
| `stage` | query | string | 否 | 全部 | 非空时必须是合法阶段枚举，否则 400 `task.invalid_stage` | `implementing` |
| `agent_type` | query | string | 否 | 全部 | 匹配 `target_agent_type` 等于该值**或为空** | `claude-code` |
| `cancelled` | query | bool | 否 | `false` | `true` 时**包含**取消态任务；`false`/缺省时**排除** | `true` |

#### 响应字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| （返回形态） | array | 是 | 裸数组，元素为任务对象；**本次不变** |
| `id` | string | 是 | 任务 id，8 位十六进制 |
| `title` | string | 是 | 任务标题 |
| `state` | string | 是 | 任务状态 |
| `stage` | string | 是 | 研发阶段 |
| `priority` | int | 是 | 优先级 |
| `target_agent_type` | string \| null | 是 | 目标 agent 类型 |
| `labels` | array | 是 | 标签列表（**唯一保留的 JSON 列**） |
| `due_at` | string \| null | 是 | 截止时间，naive UTC ISO |
| `created_at` | string | 是 | 创建时间，naive UTC ISO |

> 其余 JSON 列（`files`/`deliverables`/`doc_paths`/`doc_statuses`）**不出现在本响应**，改前亦不出现——本次只是不再从库里加载它们。

#### 错误码

| HTTP | 业务码 | 含义 | 处理建议 |

| 400 | `task.invalid_state` | 非法 state 入参 | 按 `detail.message` 修正 |
| 400 | `task.invalid_stage` | 非法 stage 入参 | 按 `detail.message` 修正 |

## 事件与推送

WebSocket `/ws` 通道与事件结构**完全不变**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `task_update` / `idea_update` / `memory_update` |
| `event.type` | string | 事件类型，如 `task.stage_advanced`、`task.completed` |
| `event.payload` | object | 事件负载 |

**本次放宽轮询间隔的前提正是这条通道**：任务列表的实时性主要由 WS 事件驱动，轮询只是兜底，因此把 `board/summary`、`ideas` 的轮询从 5 s 放宽到 30 s 不会造成看板数据滞后。

## 分页

本任务涉及的三个接口**均不分页**：`/tasks` 返回全量任务（本次明确不做分页，理由见需求 N-1），`/board/summary` 与 `/ideas` 的返回条数本来就有上限。

> 若任务表继续增长导致 `/tasks` 再次变慢，届时单独立项引入分页，届时本文档需重新定义分页参数与响应结构。

## 时间 / 数值 / 空值约定

- 时间：naive UTC ISO 字符串（不带 Z/偏移），如 `2026-11-18T09:29:36.334915`；前端按 UTC 解析。
- 数值：计数类均为整数；`priority` 为 0–3。
- 空值：`due_at` 无截止时为 `null`；`target_agent_type` 为 `null` 表示任意 agent；`labels` 为空时为 `[]`。

## 枚举全集

| 枚举 | 取值 | 含义 | 出现位置 |
|---|---|---|---|
| `TaskState` | `queued` / `claimed` / `running` / `reviewing` / `completed` / `failed` / `retrying` / `cancelled` | 任务状态 | `state` |
| `TaskStage` | `brainstorming` / `design` / `planning` / `ready` / `implementing` / `review` / `done` | 研发阶段 | `stage` |
| `TaskKind` | `normal` / `change_tracking` / `idea_review` | 任务类型 | 不在本接口返回 |

> 调用方必须能处理**未知枚举取值**：未知 `state`/`stage` 按原样透传展示，不得抛错。

## 限流与配额

- 本地单用户服务，**不限流、不配额**，无 429 响应。
- 本次的性能目标是「让正常轮询不成为负担」，而非靠限流兜底。

## 超时与并发

- 建议客户端超时：`/board/summary` ≥ 10 s（改前实测峰值 1008 ms，改后应 ≤ 100 ms）。
- 并发：多标签页同时轮询是既有形态；本次通过降低单次成本与放宽间隔共同缓解，**不引入服务端并发控制**。
- 长任务：三个接口均为同步返回，无异步任务 ID 语义。

## 文件上传与下载

本契约涉及的接口**不涉及文件上传或下载**（本节保留仅为完整性）。

## 安全与脱敏

- 只读查询，不放宽任何过滤条件。
- `cancelled=true` 仍可取到取消态任务——该参数本就为看板展示服务，属既有语义，不在本次收紧范围。
- 响应不含本地绝对路径、不含 `workspace` 内容、不含任何凭据。
- 不放宽 CORS、不新增对外暴露端口。

## 兼容性与废弃策略

- **完全兼容变更**：响应字段集合、字段名、顺序、取值语义、错误码、HTTP 状态码全部不变。
- **破坏性变更定义**（本次未触发）：响应结构变化、字段删除或改名、错误码语义变化、过滤语义变化。
- 验证方式：**改前改后对同一请求做响应体字段级 diff**，字段集合必须完全一致（FR-6），由测试用例 TC-2 兜底。
- 若后续引入分页，属破坏性变更，需先升级契约版本并通知全部消费方。
