## 0. 阅读约定与三条自律

**证据分档**（沿用 `01` §0 / `02` §0）：

| 档位 | 含义 | 写法 |
|---|---|---|
| **事实** | 代码、数据库、命令输出或**公开来源**直接证明 | 给出路径 / 命令 / 链接 + **核查日期** |
| **推断** | 由实现或数据推断，无直接证明 | 标「（推断）」+ 推断链 |
| **待验证** | 目前缺证据，是主张/假设 | 标「（待验证）」+ 验证方法 |

**三条自律（本文的防自欺规则）**：

1. **不预设创新**：任何"我们有、别人没有"的表述，先给检索方式与日期；检索不到 ≠ 不存在，只能写成「检索未发现（推断）」。
2. **机制 ≠ 效应**：机制在跑（生产有 103 次文档状态流转、96 条读证）只证明"能被强制产生"，不证明"因此变好"。
3. **概念新颖 ≠ 技术突破**：突破点必须同时满足 —— 问题真实、技术有难度、有可测量收益、且**有不成立的退出条件**。缺一条就只能叫"候选"。

## 1. 五个维度的差距判定

> 每个维度先给"事实基线"，再给"差距性质"。基线一律取 `01`/`02` 的实测值，不引用 README。

### 1.1 真实用户问题：三个问题，真实度不等

| # | 用户问题 | 真实度证据（档位） | 判定 |
|---|---|---|---|
| U1 | 多 Agent 各自为战，归属/进度/状态无事实源 | **事实**：multica 52.4k★、vibe-kanban 28.3k★、paseo 20.3k★、agent-orchestrator 13.0k★（§2 核查日 2026-10-10）——该痛点有巨量公开需求 | **真实且已商品化**：需求真实，但解法（看板+编排）是红海 |
| U2 | 规格/文档先行，避免 Agent 离题返工 | **事实**：github/spec-kit **140,641★**（§2），SDD 流程 specify→plan→tasks→implement→converge 成为事实标准 | **真实且被大厂验证**：但已被"流程模板/技能"形态满足，尚未见"服务端强制"成为主流形态 |
| U3 | 「Agent 说 done，证据在哪？」——完成声明不可核验 | **事实**：公开讨论 openai/codex#30011（2026-06-25，§2）；同方向公开项目 mcp-agent-gate、omk(evidence)、AgentClaimGuard、agent-evidence(PyPI) 并存 | **真实但需求强度未知**：同向项目 star 数 0–145（§2），**无人验证过付费/采用意愿** |
| U4 | 本项目自己声明的三痛点（谁在干/干到哪/产出在哪） | **事实**：`README.md` §1；**待验证**：外部是否有第二个人为此改变工作流（当前外部使用者 = 0，§2 mio-taskhub 元数据） | **自用侧已验证，外部侧未验证** |

**结论（推断）**：U1 真实但**无胜算**（我们 1★ vs 52.4★，且功能面差距见 §1.3）；U2 真实但**形态之争未定**（约定 vs 强制）；U3 真实但**强度未知**。**三个问题里没有任何一个已被证明"愿意为它换工具"**——这是全部方向评估的底色。

### 1.2 技术难度：真正难的不是"有没有做出来"

| 难度档 | 项 | 依据（档位） |
|---|---|---|
| **低（已被本项目做完）** | 任务状态机、看板、claim/heartbeat/submit、文档质量分与棘轮、ReadEvidence 422 门控、MCP 工具面 | 事实：`02` §3 分档 A+B+C；单人+agent 数月内建成 → **这些不构成技术壁垒，别人也能做** |
| **中（设计已完成，待实施）** | Agent 生命周期观测：两级证据 `process_alive`/`agent_ready`、本地 jsonl 真相源 + 非实时幂等 ingest、`heartbeat_sent_count` 坐实"心跳链失效" | 事实：`docs/taskhub/design-agent-lifecycle-instrumentation.md` 已过两轮评审（A1–A5 修订闭环，A6 未实施）；边界已固化（不改 reaper/timeout/门控/事务） |
| **中高（本项目独有的判定难题）** | 单机上 **C 类（心跳链失效）与网络分区本质不可分**，必须引入第二观测通道才能判定 | 事实：设计文档 R2 评审结论（该文档 §11.1）；这是**故障检测的经典难题**在单机场景的具体化 |
| **中高（实验方法难度）** | 门控行为效应的 A/B：样本**会自限**——n=16 cohort 因"系统变健康→insight 不再派生任务"而无法扩到 20 | 事实：`docs/taskhub/experiment-cohort-n16-20261002.md` §47/§64；→ **样本获取本身就是技术问题** |
| **高（不属于本项目，竞品已解决）** | 多 CLI 适配、diff 评审/worktree 隔离、桌面/移动端、多租户与权限 | 事实：multica 支持 26 个 agent CLI、roles/workspaces/VCS/IM 集成（§2）→ 追平即红海 |

**结论（事实 + 推断）**：本项目**已建成的部分难度不高**；真正有难度的是 **(a) 生命周期可判定性** 与 **(b) 小样本下的效应可证伪性**。二者都不是"新概念"能绕过的——**概念新颖在这里帮不上任何忙**。

### 1.4 可测量收益：每个方向必须先写清"拿什么数说话"

| 方向 | 基线（事实） | 可测指标 | 取数方式 |
|---|---|---|---|
| D1 生命周期 | 首启失败 ~38%（10/26）；requeue 自愈 100%；`reaper_decision` 仅 5 条 | 首启成功率（n≥100）、三分根因占比（真死/链路断/观测不足）、误回收率 | 生产库 `run`+`event` + 新增 `agent_lifecycle.*` 埋点 |
| D2 门控效应 | 生产 96 条 readevidence / 33 run；103 次文档流转；force=0 | 未读提交率、一次通过率、文档 error 占比 | 随机开关 `required_reads` 的 A/B（n≥30/组） |
| D3 完成回执 | FR↔TC 矩阵与质量分已存在；回执无消费方 | 审查者基于回执的决策一致性；篡改检出率 | 离线校验器 + 1 个真实审查场景 |

**反例提醒（事实）**：本仓库已有"计算闭环 ≠ 价值闭环"的教训——`slosnapshot` 2016 行、`depmetricssnapshot` 2 万余行在算，但 `Evidence→新 Insight` 为 **0**（`01` E10）。**任何方向若说不出"谁消费这个数"，即判为不值得做。**

### 1.5 复现难度：别人能不能验证我们的结论

| 维度 | 现状（档位） | 影响 |
|---|---|---|
| 代码复现 | 事实：Python3.12 + FastAPI + SQLite，108 个 py / ~19,475 行，1260 本地用例通过 | **低**——机制可被重建 |
| 实验复现 | 待验证：A/B 需要多 agent 执行环境 + 任务供给，且样本自限（n16 教训） | **中高**——外部无法独立复算我们的效应量 |
| 结论复现 | 事实：452 条提交历史已 squash；36 份支撑文档不入库；README 数字与事实相反（`02` §7 C1–C7） | **高**——第三方无法审计我们过去的结论 |
| 数据复现 | 事实：结论依赖**单机生产库**（383 task / 284 run），不可外部获取 | **高**——只能引用，不能核验 |

**结论（事实）**：本项目目前**对外结论的可复核性极弱**。这一点直接限制了"技术突破"宣称的可信度——**先修复可复核性（G-验证链），再谈宣称**。

## 3. 差距性质三分：已商品化 / 未验证差异 / 真实缺口

| 类别 | 内容 | 对"突破点"的含义 |
|---|---|---|
| **(A) 已商品化，不得宣称创新** | 看板、agent 注册/心跳、领取/提交、依赖与环检测、cron、MCP 接入、本地持久化、重试/超时、diff 评审、worktree 隔离、多 CLI 编排 | 事实：竞品 star 3★–52.4k★ 全有（§2）。**在此打平没有收益** |
| **(B) 未验证差异（唯一候选"突破点"）** | **门控位置**：我们把门控放在**任务生命周期的必经路径**上（submit → 422），而非 agent 自觉或工具侧建议。对照：spec-kit 的 gate 由 agent 读 checklist 自执行；mcp-approvals **自述不在网络路径上、拦不住跳过** | 推断：这是**架构位置差异**，不是概念差异。**效应与需求均未验证**（§1.4 / §2.4） |
| **(C) 真实缺口（与竞品无关也必须补）** | CI 全红、覆盖率 0、关键文档不入库、首启 38% 失败、修复后无样本、README 漂移、远端无 LICENSE、历史 squash、取消原因不落库 | 事实：`02` §9 F1/F2/F5/F6、§7。**这些是"差距"本身，不是方向**——但 D1/D2 的前置 |

**一句话（推断）**：本项目唯一可能构成技术差异的是 **(B) 门控位置**；而**当前最硬的技术差距却是 (C) 验证链与执行可靠性**。方向选择必须同时回答这两件事——先补 (C)，才谈得上验证 (B)。

## 4. 三个候选技术方向

> 上限 3 个（题目要求）。每个方向给：问题 → 方案 → 优势 → 风险 → 研发成本 → 证据要求 → 退出条件。
> 成本估算口径：**单人 + agent 辅助**，周为工作周；含设计、实现、测试与取证，不含分发运营。

### D1 · 可判定的执行生命周期（自适应失败检测 + 两级证据）

**问题（事实）**：首启失败 **~38%**（10/26），`never_started 5 + agent_offline 5`；run 成功率 **56.7%**；24/24 心跳失败经根因分析为 `progress=0`（从未工作）而非误判；修复（窗口自适应 + 有界 requeue）**已入码但生产无修复后样本**；`reaper_decision` 仅 5 条，"非误回收"**未获终局证明**。缺 agent 侧日志 → **无法区分真死 / 链路断 / 观测不足**。

**方案**：实施已过两轮评审的生命周期埋点（`agent_lifecycle.*` 事件：`process_alive` 结果态回填、`agent_ready` 以 Hub 侧首心跳判定、本地 jsonl 真相源、非实时幂等 ingest、`heartbeat_sent_count` 坐实链路失效、异步 fire-and-forget 不进关键路径），叠加 **Detect → Classify → Recover → Verify** 四级闭环（`0712a33e/review.md` 已给出分级处置：`never_started` 干净 requeue 不消耗 attempt），最终把超时判定从"固定窗口"升级为**按心跳速率/任务时长自适应的失败检测**（方向参照成熟故障检测器思路，非新发明）。

| 维度 | 评估 |
|---|---|
| **优势** | ① 问题由自有生产数据**确证**（不是假设）；② 设计已完成两轮评审、边界固化（不改 reaper/timeout/门控/事务），**实施成本已被压低**；③ 度量与取证全在本地可复现（脚本 + 只读 DB）；④ 是 D2/D3 的**硬前置**——执行噪声不除，任何 A/B 都不可信 |
| **风险** | ① **不是差异点**：竞品的 retries/timeouts 是标配（§2）→ 追平入场券而已；② 根因可能落在**外部环境**（opencode 会话启动、MCP 握手、agent CLI 不可用），项目内无法根治 → 收益上限受限；③ 埋点本身可能失效（设计文档已列 Hub 单点、进程被杀发不出等失败模式） |
| **研发成本** | **1–2 周**（埋点实施 + 分析脚本 + 根因报告）。低风险项：埋点为只读观测脚手架，可随时回滚关闭 |
| **证据要求** | n≥100 首启样本；三分根因各 n≥30 可归类；`reaper_decision` 样本 ≥30 且能区分真死/误回收/观测不足；输出**可复跑的分析脚本** |

**退出条件**：见 §7 表 D1。

### D2 · 门控效应的可证伪验证 + 门控协议化（gate-as-protocol）

**问题（待验证）**：门控/读证/棘轮在生产真实发生（103 次流转、96 条读证、force=0），但**从无对照实验证明它改变了行为或提升了质量**（`01` V1/V2）。同时其需求侧证据薄弱：同向项目 star 0–145（§2）。

**方案**：分两步、**第二步以第一步为条件**。
- **D2-a 效应实验**：同批任务随机开/关 `required_reads` 与质量门，比较 ①未读文档提交率 ②一次通过率 ③文档 error 占比 ④force/绕过率（生产基线 0 次）。
- **D2-b 协议化（条件性）**：仅当 D2-a 通过，才把门控抽成**对任意 agent CLI 生效**的接入面（MCP 中间件 / HTTP 反向代理钩子），使"提交完成"这一动作必须经过门控点——即把"一个产品的功能"变成"可被别人采纳的接入件"。

| 维度 | 评估 |
|---|---|
| **优势** | ① 这是本项目**唯一可能的差异化资产**，且 U2 需求已被 spec-kit 140★万级验证；② 若成立，价值从"自用工具"升为"可复用接入件"，天花板最高；③ 生产已有 0 次 force 的**低绕过基线**，实验起点干净 |
| **风险** | ① **需求证据偏空**（同向项目 1–145★）——可能是"没人要"而非"蓝海"；② **样本自限**（n16 教训）→ 达不到 n≥30/组则实验无结论；③ 摩擦可能反噬：门控过严会推高 force/绕过（现为 0，一旦 >10% 即劣化信号）；④ **窗口风险**：spec-kit 的 checklist gate、Consort/PactKit 类"enforcement"正在把同一件事做进 agent 侧与 CI 侧 |
| **研发成本** | D2-a **2–3 周**（实验编排、随机化、指标埋点、统计报告）；D2-b **3–6 周**（条件性，仅 D2-a 通过后启动） |
| **证据要求** | n≥30/组随机对照；未读提交率差异 p<0.05 且效应量可解释；一次通过率**不下降**；至少 **1 个非本项目使用者**实际接入并跑通一次闭环 |

**退出条件**：见 §7 表 D2。

### D3 · 可验证完成回执（completion receipt / evidence bundle）

**问题（真实度中等）**：「Agent 说 done，证据在哪」有公开讨论佐证（codex#30011），同向已有 mcp-agent-gate（防篡改回执）、AgentClaimGuard、agent-evidence(PyPI)、omk。**已有解法均为 agent 侧自报或工具侧建议**。

**方案**：把已完成的资产打包为**结构化回执**：任务终态 + ReadEvidence 指纹 + FR↔TC 追溯 + 质量分/棘轮状态 + 关键事件序列 → 落成可离线校验的 bundle（含哈希链），随 `submit_result` 产出；提供**第三方校验器**（篡改样本必须 fail-closed）。收件人是人 / CI / 审计方，三选一先验证。

| 维度 | 评估 |
|---|---|
| **优势** | ① 直击 U3 真实痛点（有公开讨论证据）；② 我们已有全部原料（状态机、指纹、追溯矩阵、事件流），**是组合而非发明**；③ 与同向项目相比，我们的回执**由服务端在必经路径上签发**，而非 agent 自报——位置更硬 |
| **风险** | ① **概念已不新颖**（至少 4 个同向公开项目）→ 按题目要求**不得据此认定突破**；② **无消费方**：回执的价值取决于"谁读它"，当前外部审查者 = 0；③ 与 CI 现成 test report 存在**增量不明**风险；④ 定义标准可能被上游（GitHub/spec-kit、MCP 治理规范）先行统一 |
| **研发成本** | **3–6 周**（schema 设计、哈希链、校验器、submit 集成、样例与测试） |
| **证据要求** | ≥1 个**真实审查场景**中，审查者基于回执做出接受/拒绝决策并确认比看日志更可靠；校验器对 100% 篡改样本 fail-closed；与"直接看 CI 结果"的对比有可述的增量 |

**退出条件**：见 §7 表 D3。

## 5. 优先方向：D1，以及为什么它优于 D2/D3

### 5.1 比较矩阵

| 维度 | D1 生命周期 | D2 门控效应+协议化 | D3 完成回执 |
|---|---|---|---|
| 真实用户问题（§1.1） | **自有生产确证**（38%/56.7%） | U2 需求真实，但**我们的门控需求未证** | U3 真实但**强度未知** |
| 技术难度（§1.2） | 中高（单机失效判定 + 样本获取） | 中（实验设计）/ 中高（协议化） | 中（组合已有件） |
| 同类能力（§1.3） | 追平入场券（**非差异**） | **唯一候选差异** | 同向已有多家 |
| 可测量收益（§1.4） | **立刻可测**（DB+埋点） | 需 n≥30/组，样本**可能自限** | **依赖外部消费方（当前 0）** |
| 复现难度（§1.5） | **低**（脚本本地可跑） | 中（实验可复算但耗样本） | 高（依赖真实审查场景） |
| 是否前置他方 | 是 D2/D3 的前置 | 被 D1 前置 | 被 D1/D2 前置 |
| 研发成本 | 1–2 周 | 2–3 周（+3–6 周条件性） | 3–6 周 |
| 失败可见性 | 高（一周内即知） | 中（受样本限制） | 低（可能长期无消费方） |

### 5.2 选择 D1 的四条理由（不是偏好，是依赖关系）

1. **逻辑前置（最强理由）**：首启失败 38%、run 成功率 56.7% 的噪声会**淹没 D2 的组间差异**，也会让 D3 把"假失败"写进回执。**先做 D1 不是保守，是实验有效性的必要条件。**
2. **不依赖任何未验证假设**：D1 的问题由自有生产数据确证；D2/D3 都建立在"外部有人需要门控/回执"上，而 §2 给出的先验是**同向项目 0–145★、本项目外部认知 0**。
3. **证据获取成本最低且完全可复现**：脚本 + 只读 DB 即可复算；D2 受样本自限威胁，D3 依赖不存在的外部消费方。
4. **有明确退出路径且已预设**：`01` §6.3 已给出降级触发（n≥100 后仍 <70% → 定位降级），本文件 §7 把它细化为可执行判据。

### 5.3 必须同时说清的两句话（防误读）

- **D1 不是技术突破，是入场券。** 它不会让本项目变得独特，只会让本项目**变得可被验证**。
- **真正的"候选突破点"是 D2（门控位置 + 效应证据），但它必须先过两道门**：D1 达标（噪声可控）+ D2-a 实验通过（效应存在）。**在两道门之前，任何"我们首创/我们更好"的表述都无证据支撑。**

## 7. 判定条件：方向成立 / 不成立（Go / No-Go）

### D1 · 可判定的执行生命周期

| | 判定条件 | 触发动作 |
|---|---|---|
| **成立** | n≥100 首启样本，**首启成功率 ≥90%**；三分根因可归类（每类 ≥30 或明确"该类不复现"）；"非误回收"获终局证明（`reaper_decision` n≥30） | 解锁 D2-a 实验；`01` T1/T2 关闭 |
| **部分成立** | 成功率 70%–90%，或根因主要落在**项目外**（agent CLI/环境） | 定位维持"个人/小团队效率工具"；把根因以可读诊断形式交付用户（已有 `_diagnose_command` 先例） |
| **不成立** | n≥100 后仍 **<70%**，或观测体系本身不可用（埋点样本不足/三分不可判） | **定位降级**：暂停一切社区增长目标（`01` §6.3）；不再投入 D2/D3，转"本地个人工具 + 明确已知限制清单" |

### D2 · 门控效应验证 + 协议化

| | 判定条件 | 触发动作 |
|---|---|---|
| **成立** | ① D1 达标（噪声可控）；② A/B n≥30/组，未读提交率差异 **p<0.05** 且一次通过率不下降；③ force/绕过率 **≤10%**（基线 0）；④ ≥1 个外部用户接入闭环 | 启动 D2-b 协议化；可对外称"**经对照验证的差异**"（仍不得称首创） |
| **不成立** | ① 样本自限导致 n 达不到（连续 4 周无法凑满）；② 无显著差异；③ 绕过率 >10%（摩擦反噬）；④ 6 个月内 0 外部接入 | **门控降级为可选特性**，定位重心移回"任务编排 + 留痕"（与 `01` §6.3 一致）；**停止协议化投入** |

### D3 · 可验证完成回执

| | 判定条件 | 触发动作 |
|---|---|---|
| **成立** | ① ≥1 个真实审查者（人或 CI）据回执作出决策并确认优于看日志；② 校验器对全部篡改样本 fail-closed；③ 与"直接看 CI/test report"相比有可陈述增量 | 纳入 submit 主链，作为对外差异化证据之一 |
| **不成立** | 回执产出 3 个月内 **0 消费**；或增量被 CI 结果完全覆盖 | **停止开发**，原料（指纹/追溯/事件流）保留在库内不打包 |

### 全局熔断（沿用 `01` §6.3）

- 出现**确证 P0**（数据损坏 / 状态不可信 / 不可恢复）→ 冻结 D1–D3，全部资源转止血。
- 3 个月外部 star <30 且外部闭环使用者 <3 → 放弃 Trending/增长叙事，本文件所有"对外宣称"条款失效，仅保留内部工程判据。

## 8. 结论（可复述版）

1. **不预设创新**：看板/编排/心跳/重试/MCP 全线已被 3★–140k★ 项目商品化（§2，核查日 2026-10-10）；本项目在这些点上无差距优势，也不该追。
2. **唯一候选差异是"门控位置"**（服务端把门控放在 submit 必经路径），**但它未经效应验证、且需求侧公开证据偏空**（同向项目 0–145★，外部对本项目认知 0）→ 只能叫候选，不能叫突破。
3. **最硬的技术差距反而是内伤**：CI 53/53 全红、覆盖率 0、关键文档不入库、首启失败 38%、结论不可复核——**这些不修，任何"突破"宣称都缺可核验性**。
4. **优先方向 = D1（可判定的执行生命周期）**：它是 D2/D3 的实验前置、问题已被自有数据确证、成本 1–2 周、结论可本地复现、退出条件明确。**它不是突破，是让"突破是否存在"变得可判定的前提。**
5. **D2 保留为唯一突破候选**，须先过 D1 达标与 A/B 两道门；**D3 排在其后**，须先找到回执的消费方。
6. **10 项功能停/冻、6 条主张必须先实验**（§6），未出结论前禁止对外使用"质量提升/闭环/生产级/首创"等表述。
